# WOBKEY Crush 80 Reboot Pro RGB — исправления macOS/VIA

[English](README.md)

Воспроизводимые патчи для **WOBKEY Crush 80 Reboot Pro RGB** на основе
официальной прошивки WOBLAB от 2026-06-18, USB-версия **0108**.

Текущая версия — [**NativeHeld — v1.3.0**](https://github.com/tarzst/wobkey-crush80-reboot-pro-firmware/releases/tag/v1.3.0).
Она добавляет полную поддержку слоёв QMK/VIA (`MO`, `TG`, `TO`, `DF`, `OSL`,
`TT`, `FN_MO13`/`FN_MO23` Tri-Layer, сквозной `KC_TRNS`), Tap-Hold клавиш
(`MT(mod, kc)` и `LT(layer, kc)`) с автоповтором **Quick Tap** и двусторонним
rolling-safe **Permissive Hold**, режим **Caps Word** (`Both Shifts` или `0x7C73`
`CW_TOGG`), One-Shot модификаторов (`OSM`), `LM(layer, mod)`, `KC_GESC`, нативных
сочетаний с удержанием (`QK_MODS`), а также включает аппаратный сторожевой
таймер (Watchdog ~4.0 с) и исключает лишние перезаписи Flash при загрузке
раскладки в VIA.

**Экспериментальная версия, проверенная на одной клавиатуре. Это не полный порт QMK.**
Перед использованием прочитайте [границы проверки и ограничения](docs/NATIVEHELD.md).

## Что исправляет NativeHeld

Штатная прошивка в macOS накладывает жёсткую трансляцию модификаторов и F-ряда
поверх назначений VIA. Патчи позволяют управлять результатом через раскладку:

- Windows использует слои **0/1**, macOS — **2/3**, включая пользовательский F-ряд.
- Сквозной `KC_TRNS` ищет назначение сверху вниз по всем активным слоям
  (`3 -> 2 -> 1 -> 0`) вплоть до базы текущей ОС (`0` для Win, `2` для Mac или `DF`).
- Полный набор операторов слоёв QMK/VIA: `MO`, `TG`, `TO`, `DF`, `OSL`
  (One-Shot Layer), `TT` (Tap-Toggle), `LM(layer, mod)` и `FN_MO13` / `FN_MO23` Tri-Layer.
- Tap-Hold клавиши `MT(mod, kc)` (`0x2000..0x3FFF`) и `LT(layer, kc)`
  (`0x4000..0x43FF`) с порогом 200 мс, автоповтором **Quick Tap** (`Tap -> Hold`
  в пределах 200 мс удерживает `kc`), `HOLD_ON_OTHER_KEY_PRESS` для `LT` и
  двусторонним rolling-safe **Permissive Hold** для `MT`.
- Режим **Caps Word** (`Both Shifts` `KC_LSFT + KC_RSFT` или `0x7C73` `CW_TOGG`):
  автоматически зажимает `Shift` для `A..Z` и `-` (`_`), сохраняет режим на
  цифрах `1..0`, `Backspace` и `Delete`, и выключается на `Space` или других клавишах.
- One-Shot модификаторы `OSM(mod)` (`0x52A0..0x52BF`) с накоплением цепочки и
  переходом в обычное удержание, а также `KC_GESC` (`0x7C16`: `Esc` обычно,
  `~` / `` ` `` при `Shift` / `GUI`).
- Нативные сочетания `QK_MODS` удерживают модификаторы и основную клавишу до
  отпускания физической кнопки. Если отпустить Fn первым, отпускается именно
  действие, выбранное при нажатии.
- Общий модификатор или код клавиши остаётся нажатым, пока его использует хотя
  бы одна удерживаемая кнопка или другое активное действие.
- Включён и обслуживается на каждой итерации главного цикла аппаратный Watchdog
  Telink B91 (`0x8014014C = 0x0B700000` ~4.0 с, `0x80140142 = 0x80`), а также
  устранён заводской конфликт бита `gp+804 & 0x20` между `MO(1)` и сохранением
  настроек RGB в сектор Flash `0x8A000`.
- Поддерживаются VIA keymap, энкодер, RGB и 16 слотов макросов. Заменённый
  обработчик исправляет чтение конца буфера макросов в usevia.app и сохраняет
  байт 511 при записи.

В проверенной Mac-раскладке используются Shift+GUI+5, Ctrl+GUI+Q, GUI+Q,
Ctrl+Up и GUI+Space, а также `MT`, `LT`, `OSL` и `OSM`.

К релизу NativeHeld приложены прошиваемый `.bin`, эталонный `.elf` с кодом
заменённых компонентов, `manifest.json` и `SHA256SUMS`.
**ELF предназначен для анализа, не для прошивки.** Автоматические архивы
исходников GitHub содержат код патча, сборщик, тесты и документацию.
Оригинальная прошивка производителя остаётся проприетарной: здесь опубликованы
исходники патча и заменённых компонентов, а не всей заводской прошивки.

## Установка NativeHeld по USB

1. Экспортируйте раскладку и макросы из VIA, запишите настройки RGB.
   **OTA сбрасывает настройки.**
2. Скачайте и распакуйте архив исходников из релиза NativeHeld либо клонируйте тег:

   ```bash
   git clone --branch v1.3.0 --depth 1 \
     https://github.com/tarzst/wobkey-crush80-reboot-pro-firmware.git
   cd wobkey-crush80-reboot-pro-firmware
   ```

3. Нужны Python 3 и системная библиотека HIDAPI. На macOS: `brew install hidapi`.
   Python-пакеты не требуются: прошиватор обращается к HIDAPI напрямую.
   На Linux пользователю также нужен доступ к HID-устройству клавиатуры.
4. Подключите клавиатуру кабелем в проводном режиме, закройте VIA и другие
   приложения, использующие её HID-интерфейсы. Из каталога репозитория выполните:

   ```bash
   python3 tools/crush80.py info
   python3 tools/crush80.py flash \
     firmware/patched/Crush80-RGB-0108-NativeHeld-20261101.bin --yes
   ```

Прошиватор проверяет точный хеш образа и разрешённый исходный CRC, ждёт
подтверждения OTA и после перезапуска проверяет CRC **2f4f4974** на новом
соединении. Неизвестные образы и исходные версии отклоняются. Список переходов
и границы их аппаратной проверки описаны в [политике прошивки](docs/NATIVEHELD.md#flasher-policy).
После обновления восстановите настройки и проверьте назначения после переподключения.

Для проверки пакетов без открытия устройства:

```bash
python3 tools/crush80.py dry-run \
  firmware/patched/Crush80-RGB-0108-NativeHeld-20261101.bin
```

Политика прошиватора допускает откат на официальную 0108 и RC2.
Для программного отката нужен работающий OTA-интерфейс. Если клавиатура
перестанет определяться, восстановление программным способом не гарантируется.

## Проверки и известные ограничения

На одной клавиатуре подтверждены нативные удержания на **macOS по USB**,
Fn-слои, доступ к макросам и их воспроизведение через VIA, печать по BLE,
сохранность нативной раскладки, макросов и RGB после переподключения.
Эффект 5 одинаково работал после USB → BLE → USB. Нативные сочетания по
BLE/2.4 ГГц аппаратно не проверены.

- В штатном USB-отправителе остаётся гонка, воспроизведённая в эмуляторе:
  прерывание во время копирования FIFO и сброса флага изменений может привести
  к потере обновления отчёта, включая отпускание. Эта сборка её не исправляет;
  на железе пользователь её не наблюдал.
- Не проверены на железе все варианты сна, переполнения и вложенных прерываний.
- Исправление байта 511 проверено офлайн. Аппаратный бэкап уже содержал там
  ноль, поэтому чтение обратно не было независимой проверкой исправления.
- Заводской эффект RGB **11** после включения может визуально стать эффектом
  **2**, хотя VIA продолжает читать 11. Патч не меняет запуск RGB.

Подробности: [описание NativeHeld, сборки и проверок](docs/NATIVEHELD.md).

## Сборка и тесты

Сборка NativeHeld из C/assembly требует эталонного RISC-V GCC toolchain:

```bash
python3 src/build_nativeheld.py --cc /path/to/riscv64-unknown-elf-gcc
```

Сборщик требует точного совпадения хешей секций и итогового образа с проверенной
версией. Инструменты и размещение кода описаны в
[NATIVEHELD.md](docs/NATIVEHELD.md#reproduce-from-c-and-assembly).

Воспроизведение предыдущего патча RC2:

```bash
python3 src/build_firmware.py \
  firmware/official/Crush80-RGB-20260618-official.bin \
  /tmp/Crush80-RGB-20260618-MacLayers-RC2.bin
```

Публичные тесты проверяют артефакты и сценарии C-кода на хосте:

```bash
python3 -m unittest discover -s tests -v
```

История и детали: [технический отчёт RC2](docs/TECHNICAL.ru.md),
[план разработки](docs/VIA-ROADMAP.ru.md) и [контекст проекта](CONTEXT.md).
