# Технический отчёт: Crush 80 RGB 20260618 Mac-layers RC2

## Устройство и официальная база

Целевая клавиатура: WOBKEY Crush 80 Reboot Pro RGB, USB VID:PID `320f:5055`.
Официальный образ получен из WOBLAB RGB updater от 2026-06-18.

* raw size: `124436`;
* SHA-256: `b1dcb56d42c0a2fad1006d572392630a5d4c15f92b63f1701784f732426886da`;
* OTA CRC: `ca2d85dc`;
* USB `bcdDevice`: `0108`.

Точная официальная база была установлена штатным Windows updater на целевую
клавиатуру. После холодного запуска подтверждены USB, OTA, VIA protocol 11,
четыре слоя и CRC `ca2d85dc`.

## Исходная ошибка

В заводском keymap слои 2 и 3 являются копиями слоя 0, а Fn на всех слоях
назначен как `MO(1)`. После загрузки пользовательского layout отдельные значения
на слоях 2/3 читаются обратно, но Mac-режим продолжает использовать 0/1 и
переписывает F-ряд и модификаторы скрытой логикой после чтения VIA keycode.

V0108 нативно исправляет другую ошибку старых прошивок: команда VIA
`DYNAMIC_KEYMAP_SET_BUFFER` (`0x13`) имеет настоящий обработчик по адресу
`0xDC40`. Аппаратная загрузка полного layout через usevia.app прошла успешно.

## Патч скрытой трансляции

Четыре чтения Win/Mac flag заменены константой 0 только в путях скрытой
keycode-трансляции:

| Offset | До | После |
|---:|---|---|
| `0x12C5C` | `03c6a801` | `13060000` |
| `0x13258` | `834fab01` | `930f0000` |
| `0x13338` | `8342ab01` | `93020000` |
| `0x134F8` | `8342ab01` | `93020000` |

Глобальный Win/Mac flag не меняется: он остаётся доступен для выбора пары
слоёв.

## Выбор слоёв

Штатная загрузка текущего dynamic layer по адресу `0x13230` перенаправлена в
28-байтный блок в нулевом code cave `0x10A8`:

```text
0x10A8  active = dynamic_layer
0x10AC  os_flag = win_mac_flag
0x10B0  if os_flag == 0: resume
0x10B4  limit = 2
0x10B8  if active >= 2: resume
0x10BC  active += 2
0x10C0  resume at 0x13234
```

Получается отображение:

| Режим | active 0 | active 1 | active 2 | active 3 |
|---|---:|---:|---:|---:|
| Windows | 0 | 1 | 2 | 3 |
| macOS | 2 | 3 | 2 | 3 |

Повторное смещение 2/3 исключено, поэтому `MO(3)` на Mac base layer работает
корректно.

## Граница diff

Патчированный образ имеет SHA-256
`7663f2fc7357ce3f4ae7f1331577c8e0f2a1bd0f7b1c038a89a6efab31ce7d88`,
OTA CRC `fe1aa4c2` и тот же размер `124436`.

Фактически изменены 49 байт. Они ограничены code cave, пятью указанными
инструкциями и четырьмя байтами CRC. Boot, USB initialization, OTA, transport,
flash save, VIA `0x13` и RGB код побайтно совпадают с официальной базой.

## Аппаратный тест

Перед OTA клавиатура сообщила официальный CRC `ca2d85dc`. Передача 7778
16-байтных блоков завершилась явным OTA success. После перезапуска был открыт
новый HID handle и получен CRC RC2 `fe1aa4c2`.

Проверено пользователем:

* полный layout сохраняется и загружается через web VIA;
* Windows использует 0/1, macOS использует 2/3;
* пользовательские назначения F-ряда больше не перебиваются;
* wired RGB сохраняется после нескольких минут полного обесточивания;
* клавиатура штатно работает после OTA и холодного запуска.

## Заводской RGB-дефект

Effect ID 11 сохраняется правильно: VIA после холодного запуска читает 11. Но
RGB-движок визуально запускает effect 2. Остальные effect ID 0–18 работают и
сохраняются. Дефект наблюдался как на заводской V0101, так и на официальной
V0108 до патча.

RC2 не вмешивается в RGB startup. Это сохраняет доказанно рабочую официальную
инициализацию и исключает повторение риска старых экспериментальных startup
hooks. Практический обход — не выбирать effect 11.

## Защита прошивальщика

`tools/crush80.py` принимает только точные SHA-256 официального V0108 и RC2.
RC2 разрешён лишь поверх CRC `ca2d85dc` или самого `fe1aa4c2`. OTA считается
успешной только после явного success response и чтения ожидаемого CRC через
свежее подключение HID.
